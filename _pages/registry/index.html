What is Apicurio Registry?

Apicurio Registry is an open source schema registry and API registry. It is a runtime server that stores, versions, validates and governs the contracts your systems depend on: event schemas such as Apache Avro, Protobuf and JSON Schema; API definitions such as OpenAPI, AsyncAPI and GraphQL; and, more recently, AI agent cards, MCP tool definitions and LLM prompt templates. Producers, consumers, CI pipelines and AI agents read and write those artifacts through a REST API, a web console, a CLI, a Maven plugin and client SDKs.

Apicurio Registry is licensed under the Apache License 2.0 and is a Cloud Native Computing Foundation (CNCF) Sandbox project. It runs anywhere a container runs, and an operator installs and manages it on Kubernetes and OpenShift.

Use cases

Schema registry for Apache Kafka and event streaming

Data published to Kafka topics and message queues must be serialized and validated against a schema. Rather than packaging schemas in every application, register them once and reference them at runtime. Apicurio Registry ships Kafka serializers and deserializers (SerDes) for Avro, Protobuf and JSON Schema, and Kafka Connect converters, so producers and consumers resolve schemas automatically. A schema registry gives you:

  • Producers and consumers decoupled from schema files
  • Producers that can be upgraded without upgrading consumers
  • A central record of every schema used in production
  • Documentation of the data format each topic or queue expects
  • Centralized control of data format and schema evolution through compatibility rules

API registry

Register OpenAPI, AsyncAPI, GraphQL and other API designs so API consumers can browse and search the APIs available in production, inspect a single API, and generate client code from the stored definition. Versioning and content rules keep published APIs from drifting into invalid or breaking states.

Agent registry and MCP registry for AI systems

AI agents need the same thing services need: a trustworthy place to discover what exists and what contract it follows. Apicurio Registry stores A2A agent cards, MCP server and tool definitions, prompt templates and model schemas as versioned, validated artifacts, and serves them through standard discovery endpoints. See Apicurio Registry for AI agents for details.

Drop-in replacement for Confluent Schema Registry clients

Apicurio Registry implements the Confluent Schema Registry API (v7 and v8), so existing Confluent serializers and tools work by pointing schema.registry.url at /apis/ccompat/v7. See the Apicurio Registry and Confluent Schema Registry comparison.

Key features

FeatureWhat you get
Artifact types Avro, Protobuf, JSON Schema, OpenAPI, AsyncAPI, GraphQL, Kafka Connect schema, OpenRPC, Thrift, WSDL, XML and XSD, plus AI artifact types: A2A agent cards, MCP tools, prompt templates and model schemas (MCP server definitions are added in 3.4). You can also add custom artifact types.
Content rules Validity, compatibility and integrity rules at global, group and artifact level. Compatibility modes: BACKWARD, FORWARD and FULL, each with a transitive variant.
Kafka integration Serializers and deserializers for Avro, Protobuf and JSON Schema, and Kafka Connect converters for Avro, JSON Schema and Protobuf.
Confluent compatibility Confluent Schema Registry API v7 and v8 under /apis/ccompat/.
Storage PostgreSQL (recommended for production), Apache Kafka, in-memory H2 for development, and read-only GitOps and KubernetesOps storage (experimental).
Security OpenID Connect authentication (for example Keycloak or Microsoft Entra ID) and role-based authorization.
Tooling Web console, REST API, CLI, Maven plugin and client SDKs.
AI agents A2A agent registry, MCP server, MCP tool discovery and an AI Catalog / ARD discovery endpoint. Several of these are experimental and disabled by default.
Deployment Container images for Docker and Podman, and an operator for Kubernetes and OpenShift.

How it works

Artifacts are organized into groups and carry a history of versions. Each new version is checked against the rules configured for it, so an incompatible schema change is rejected before it reaches a producer rather than after it breaks a consumer. Clients fetch artifacts by group, artifact and version, by content ID, or by global ID; the Kafka SerDes embed the ID in each message so consumers can resolve the exact schema used to write it.

Artifacts can also be managed declaratively. With GitOps storage, Apicurio Registry serves read-only content loaded from a Git repository; with KubernetesOps storage, from Kubernetes ConfigMaps. Both are experimental, and both let schema changes go through the same review process as code.
