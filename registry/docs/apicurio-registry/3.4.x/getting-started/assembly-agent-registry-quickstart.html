Agent registry quick start

You can use Apicurio Registry as a central registry for AI agents, MCP servers and tools, and prompt templates. In about five minutes, you start Apicurio Registry with a demo catalog, discover agents and tools, connect an AI assistant by using the Model Context Protocol (MCP), and see a compatibility rule reject an incompatible tool change.

Agent registry overview

Apicurio Registry functions as both an A2A (Agent-to-Agent) agent that exposes its own capabilities and an agent registry that stores and serves the agent cards that other AI agents publish for discovery.

As an A2A agent, Apicurio Registry exposes capabilities such as schema validation, artifact management, and agent discovery.

The A2A protocol is a standard that AI agents use to discover and communicate with each other through well-known endpoints. MCP (Model Context Protocol) is a standard that LLM-powered tools such as Claude Desktop use to interact with external services and data sources.

Apicurio Registry supports the following AI and ML artifact types:

  • AGENT_CARD: A2A agent card that describes an agent, its skills, and its capabilities

  • PROMPT_TEMPLATE: versioned prompt template with variable substitution for LLM interactions

  • MODEL_SCHEMA: input and output schema definition for an AI or ML model

  • MCP_TOOL: MCP tool definition that describes a tool, its input parameters, and its output schema

  • MCP_SERVER: MCP server definition that references the MCP_TOOL artifacts of the tools it provides

Starting the agent registry quick start

You can start Apicurio Registry with the agent features enabled, the web console, and a demo catalog by using one Docker Compose command. The stack stores its data in PostgreSQL, so the catalog survives a restart.

The quick start stack is for local evaluation only. It has no authentication, and its database password is a fixed demo value. The agent features are experimental, and the stack uses the latest-snapshot images, which contain the most recent development build.
Prerequisites

  • Docker with Docker Compose v2 is installed

  • git and curl are installed

Procedure

  1. Clone the Apicurio Registry repository and change to its directory:

    git clone https://github.com/Apicurio/apicurio-registry.git
cd apicurio-registry

  2. Start the stack:

    docker compose -f distro/docker-compose/ai-agent-registry/docker-compose.yml up -d

    The stack starts PostgreSQL, Apicurio Registry with the agent features enabled, and the web console. A seed container then loads the demo catalog into the demo group and exits.

Verification

  1. Check that the demo catalog is loaded:

    docker compose -f distro/docker-compose/ai-agent-registry/docker-compose.yml logs seed

    The output ends with Demo catalog ready in group 'demo'. The catalog contains the following artifacts:

    • weather: an MCP_SERVER that references its get_forecast tool

    • weather.get_forecast: an MCP_TOOL with a BACKWARD compatibility rule

    • translator-agent and sentiment-agent: AGENT_CARD artifacts

    • support-reply: a PROMPT_TEMPLATE

      The seed container loads only the artifacts that do not exist yet, so restarting the stack does not change the catalog.

  2. Open the web console at http://localhost:8888 and browse the demo group. The Agents tab lists the two agent cards.

Discovering agents and tools in the demo catalog

AI agents and orchestrators find agents and tools in Apicurio Registry through well-known discovery endpoints, without knowing the group or artifact ID in advance.

Prerequisites

  • The quick start stack is running

Procedure

  1. Find the agents that have a translation skill:

    curl "http://localhost:8080/.well-known/agents?skill=translation"

    The response lists the translator-agent agent card.

  2. Retrieve the Agentic Resource Discovery (ARD) catalog, which lists every agent and tool that Apicurio Registry publishes:

    curl http://localhost:8080/.well-known/ard.json

  3. Search the catalog by name:

    curl -X POST http://localhost:8080/.well-known/ard/search \
  -H "Content-Type: application/json" \
  -d '{"query": {"text": "transla"}}'

    The results list contains the Translation Agent.

  4. List the tools that the weather MCP server provides:

    curl http://localhost:8080/apis/registry/v3/groups/demo/artifacts/weather/versions/1/references

    The server version references weather.get_forecast version 1.

Connecting an AI assistant by using MCP

You can connect an MCP client, such as Claude Desktop or an IDE assistant, to the Apicurio Registry MCP server. The MCP server runs as a container that the client starts and talks to over standard input and output, and it reaches Apicurio Registry through the Docker network of the quick start stack.

Prerequisites

  • The quick start stack is running

  • An MCP client that can start a local command, such as Claude Desktop

Procedure

  1. Add the Apicurio Registry MCP server to the MCP configuration of your client. In Claude Desktop, open Settings > Developer > Edit Config:

    {
  "mcpServers": {
    "apicurio-registry": {
      "command": "docker",
      "args": [
        "run", "-i", "--rm",
        "--network", "ai-agent-registry_default",
        "-e", "REGISTRY_URL=http://apicurio-registry:8080",
        "-e", "QUARKUS_OIDC_TENANT_ENABLED=false",
        "quay.io/apicurio/apicurio-registry-mcp-server:latest-snapshot"
      ]
    }
  }
}

  2. Restart the client.

Verification

  • Ask the assistant a question about the catalog, for example: "Which agents in Apicurio Registry can translate?"

    The assistant uses the MCP server tools, such as search_artifacts, and answers with the Translation Agent.

Seeing a compatibility rule reject an incompatible tool change

A registry is more than a catalog: rules decide which changes are accepted. The demo weather.get_forecast tool has a BACKWARD compatibility rule, so a new version must accept every call that the previous version accepted. In this procedure, you try to make a new parameter required, which would break existing callers.

Prerequisites

  • The quick start stack is running

  • You are in the root directory of the Apicurio Registry repository

Procedure

  • Try to create version 2 of the tool, which adds a required units parameter:

    curl -X POST http://localhost:8080/apis/registry/v3/groups/demo/artifacts/weather.get_forecast/versions \
  -H "Content-Type: application/json" \
  -d @distro/docker-compose/ai-agent-registry/test/get-forecast-v2-incompatible.json
Verification

  1. Apicurio Registry rejects the version with HTTP status 400. The response names each incompatible change, including A property was made 'required'. at /inputSchema/required/1.

  2. Check that the accepted version is unchanged:

    curl http://localhost:8080/apis/registry/v3/groups/demo/artifacts/weather.get_forecast/versions

    The tool has only version 1. Agents that use this tool keep getting the definition that they were built against.

Importing tools from a running MCP server

Instead of writing MCP_TOOL artifacts by hand, you can import the tools of a running MCP server, and import them again when the server changes. The same compatibility rules apply, so an incompatible tool change is rejected on import.

Importing tools from a running MCP server is planned for Apicurio Registry 3.4 and is not available in released versions. For the planned behavior, see MCP tool definition features.

Stopping the quick start stack

Procedure

  • Stop the stack and keep the catalog:

    docker compose -f distro/docker-compose/ai-agent-registry/docker-compose.yml down

    To also delete the catalog, add the -v option. The next up loads the demo catalog again.
