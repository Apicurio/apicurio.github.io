Installing Apicurio Registry on OpenShift

Install Apicurio Registry on OpenShift Container Platform.

Additional resources

  • Apicurio Registry source repository

Installing Apicurio Registry from the OpenShift OperatorHub

You can install the Apicurio Registry Operator on your OpenShift cluster from the OperatorHub, which is available from the OpenShift Container Platform web console.

The OperatorHub provides an interface for cluster administrators to discover and install Operators. For more details, see Understanding OperatorHub.

You can install more than one replica of Apicurio Registry depending on your environment. The number of replicas depends on the number and type of artifacts stored in Apicurio Registry and on your chosen storage option.
Prerequisites

  • Ensure that you have cluster administrator access to an OpenShift cluster.

Procedure

  1. In the OpenShift Container Platform web console, log in using an account with cluster administrator privileges.

  2. Create a new OpenShift project:

    1. In the left navigation menu, click Home, Project, and then Create Project.

    2. Enter a project name, for example, my-project, and click Create.

  3. In the left navigation menu, click Operators and then OperatorHub.

  4. In the Filter by keyword text box, enter registry to find the Apicurio Registry Operator.

  5. Read the information about the Operator, and click Install to display the Operator subscription page.

  6. Select your subscription settings:

    • Update Channel: Select one of the following:

      • 3.x: Rolling channel that follows the latest minor version. For example, an installation of 3.3.x upgrades to 3.4.x. This is the default channel.

      • A minor-version channel, such as 3.4.x: Includes patch updates only, such as 3.4.1 and 3.4.2. For example, an installation on the 3.3.x channel ignores 3.4.x.

    • Installation Mode: Select one of the following:

      • All namespaces on the cluster (default)

      • A specific namespace on the cluster, and then select my-project.

    • Approval Strategy: Select Automatic or Manual.

  7. Click Install, and wait a few moments until the Operator is ready for use.

Installing the Apicurio Registry Operator with installation manifests

To install the Apicurio Registry Operator on a Kubernetes cluster without Operator Lifecycle Manager (OLM), apply an installation manifest from the operator/install directory of the Apicurio Registry repository.

The directory holds the following manifests:

  • apicurio-registry-operator-<version>.yaml is the all-namespaces manifest. It installs the Apicurio Registry Operator with cluster-wide role-based access control (RBAC) permissions. The Apicurio Registry Operator watches ApicurioRegistry3 resources in all namespaces.

  • apicurio-registry-operator-namespaced-<version>.yaml is the single-namespace manifest, which is available for version 3.3.2 and later. It installs the Apicurio Registry Operator with namespace-scoped RBAC permissions. The Apicurio Registry Operator watches only its own namespace. This manifest also creates a ClusterRole that lets the Apicurio Registry Operator list ApicurioRegistry3 resources and read the custom resource definition. The names of the ClusterRole and the ClusterRoleBinding end with the namespace, so you can apply the manifest in more than one namespace. All installations share the custom resource definition.

Both manifests name the namespace PLACEHOLDER_NAMESPACE in the Deployment and in the subjects of the role bindings. The other namespaced resources, such as the ServiceAccount, set no namespace and take it from the -n option of kubectl. When you apply a manifest, replace PLACEHOLDER_NAMESPACE with your namespace and pass the same namespace in the -n option.

If you apply the single-namespace manifest in a namespace that already runs an all-namespaces installation, the ClusterRole and ClusterRoleBinding of the earlier installation remain. They keep granting cluster-wide permissions to the Apicurio Registry Operator service account. Delete them after you apply the single-namespace manifest. Every all-namespaces installation on the cluster shares these two resources, so delete them only when no such installation remains:

kubectl delete clusterrolebinding apicurio-registry-operator-clusterrolebinding
kubectl delete clusterrole apicurio-registry-operator-clusterrole
Prerequisites

  • You have cluster administrator access to a Kubernetes cluster.

  • You have installed the kubectl command-line tool.

Procedure

  1. Create the namespace for the Apicurio Registry Operator:

    kubectl create namespace apicurio-system

  2. Download the installation manifest for your version from the operator/install directory.

  3. Replace PLACEHOLDER_NAMESPACE with the namespace, and apply the manifest in that namespace. For the all-namespaces manifest:

    sed "s/PLACEHOLDER_NAMESPACE/apicurio-system/g" apicurio-registry-operator-<version>.yaml | kubectl apply -n apicurio-system -f -

    For the single-namespace manifest:

    sed "s/PLACEHOLDER_NAMESPACE/apicurio-system/g" apicurio-registry-operator-namespaced-<version>.yaml | kubectl apply -n apicurio-system -f -
Verification

  • Verify that the Apicurio Registry Operator pod is running:

    kubectl get pods -n apicurio-system
