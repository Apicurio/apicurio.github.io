Apicurio Registry Operator configuration reference

You can use the following reference information to configure Apicurio Registry instances by using the ApicurioRegistry3 custom resource.

ApicurioRegistry3 custom resource structure

The ApicurioRegistry3 custom resource defines the desired state of an instance of Apicurio Registry. The resource is organized into three sections under spec:

apiVersion: registry.apicur.io/v1
kind: ApicurioRegistry3
metadata:
  name: example-registry
spec:
  app:
    # Configuration for the Apicurio Registry backend (REST API) component.
  ui:
    # Configuration for the Apicurio Registry web console component.
  consolePlugin:
    # Configuration for the OpenShift Console plugin component.

The operator provides first-class support for OAuth (OAUTHBEARER) authentication through the auth field. For other SASL mechanisms such as SCRAM-SHA-512, the recommended approach is to use the Strimzi Kafka Access Operator through the kafkaAccessSecretName field (available starting with Apicurio Registry version 3.2.0). Alternatively, you can use custom environment variables through the spec.app.env field to configure the Kafka client properties directly. See the additional resources for available apicurio.kafkasql.* configuration properties.

Configure KubernetesOps storage (read-only, experimental). Loads registry data from Kubernetes ConfigMaps:

Table 14. KubernetesOpsSpec
Field Description Type Default

registryId

Unique identifier for this registry instance. Only ConfigMaps with a matching label will be loaded. Required.

String

None

namespace

Kubernetes namespace to watch for ConfigMaps.

String

Current namespace

refreshEvery

Minimum period between polls for ConfigMap changes. Supports duration formats such as 10s, 1m, or ISO 8601 PT10S. When omitted, the operator does not set the property and the application default applies.

String

10s (application default PT10S)

labelRegistryId

Label key used to identify ConfigMaps belonging to this registry.

String

apicurio.io/registry-id

watchEnabled

Enable Watch API for real-time ConfigMap change detection. Set to false to use polling only.

Boolean

true

watchReconnectDelay

Base delay before reconnecting after watch failure. Uses exponential backoff up to 5 minutes.

String

10s
KubernetesOps storage is an experimental feature. The operator automatically enables the experimental features gate when this storage type is configured.

Example:

spec:
  app:
    storage:
      type: kubernetesops
      kubernetesops:
        registryId: my-registry
        namespace: apicurio

Example with custom polling and watch settings:

spec:
  app:
    storage:
      type: kubernetesops
      kubernetesops:
        registryId: my-registry
        namespace: apicurio
        refreshEvery: 10s
        watchEnabled: true
        watchReconnectDelay: 5s
KubernetesOps storage is read-only. All changes must be made by creating or updating ConfigMaps. For more details on ConfigMap format and RBAC requirements, see the additional resources.

GitOps storage is an experimental feature. The operator automatically enables the experimental features gate when this storage type is configured.

Example with pull mode over HTTPS:

spec:
  app:
    storage:
      type: gitops
      gitops:
        registryId: prod
        repos:
          - url: https://github.com/my-org/my-registry-data.git
            branch: main

Example with push mode:

spec:
  app:
    storage:
      type: gitops
      gitops:
        mode: push
        registryId: prod
        push:
          authorizedKeys:
            name: gitops-push-authorized-keys
          hostKey:
            name: gitops-push-host-key
GitOps storage is read-only. All changes must be made through Git. The operator injects the sync sidecar container, named apicurio-registry-gitops-sync, and a shared emptyDir volume mounted at /repos in both containers. To override the sidecar image or to add environment variables to the sidecar, use spec.app.podTemplateSpec with the container name apicurio-registry-gitops-sync. For details on the repository data format and the sync container, see the additional resources.

Kubernetes-native authentication is an experimental feature. The operator does not enable the experimental features gate for it, so you must also add the APICURIO_FEATURES_EXPERIMENTAL_ENABLED environment variable with the value true to spec.app.env; otherwise, the Apicurio Registry pod fails at startup. Do not set spec.app.auth.enabled to true at the same time, because Kubernetes-native authentication and OpenID Connect cannot be enabled together.

Example:

spec:
  app:
    env:
      - name: APICURIO_FEATURES_EXPERIMENTAL_ENABLED
        value: "true"
    auth:
      kubernetesAuth:
        enabled: true
        apiAudiences: https://kubernetes.default.svc
        groupMapping:
          adminGroups: cluster-admins
          developerGroups: developers
          readOnlyGroups: viewers
      authz:
        enabled: true

The Apicurio Registry service account also needs permission to call the TokenReview API. For the required ClusterRoleBinding and the corresponding environment variables, see Configuring Apicurio Registry Kubernetes-native authentication.

Custom resource status

The Apicurio Registry Operator reports the state of each ApicurioRegistry3 resource in status.conditions. Each condition has a type, a status of True, False, or Unknown, a reason, a human-readable message, a lastTransitionTime, and a lastUpdateTime. The status.observedGeneration field records the generation of the resource that the status describes.

Table 29. Status conditions
Condition type Meaning

Ready

Always reported. True with reason ActiveDeploymentsAvailable when all active Deployments of the instance are available. False with reason ActiveDeploymentUnavailable when at least one Deployment is not available; the message names the unavailable Deployments.

ValidationError

Reported only while it is True, with reason Error. The custom resource contains an invalid combination of fields, for example both replicas and autoscaling on the same component, a container without a name in podTemplateSpec, or environment variables set on the component container in podTemplateSpec instead of in env. The message lists the validation errors.

OperatorError

Reported only while it is True. The Apicurio Registry Operator encountered an unexpected error while reconciling the resource. The reason is the name of the exception class, and the message contains the error details.

To inspect the conditions of an instance, display the resource and read its status.conditions field. The resource is also available under the short name registry3:

kubectl get apicurioregistries3 example-registry -o yaml
